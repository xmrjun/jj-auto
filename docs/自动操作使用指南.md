# AI 建议与自动操作

[文档目录](README.md) · [安装与使用](使用指南.md) · [排查与验证](排查与验证.md)

主窗口下方新增 “AI” 下拉框和红色“紧急停止”按钮：

| 模式 | 做什么 | 会不会动鼠标 |
|---|---|---|
| AI：关闭（默认） | 只记牌，和原 Han 记牌器一样 | 不会 |
| AI：只给建议 | 识别手牌、底牌和三家出牌，用 DouZero 计算建议出牌、叫分建议和计划点击位置 | 不会 |
| AI：自动操作 | 在“只给建议”的基础上，自动叫分/加倍、选牌、点“出牌/不出”，并逐步核对画面 | 会，需要确认 |

每次启动程序或“重启识别”后都回到“关闭”，自动操作不会跨启动保持开启。

> 使用自动化工具可能违反游戏平台用户协议，账号风险由使用者自行承担。本程序不读取游戏内存、不修改游戏文件、不尝试绕过平台检测，只看屏幕、点鼠标。

## 1. 安装

按[安装与使用](使用指南.md#安装依赖)装好 Python 依赖后，在项目目录执行一次（这是唯一需要联网的步骤）：

```powershell
python scripts/fetch_models.py
```

它从固定提交下载两类文件，并逐个与 `security/model-manifest.json` 中的 SHA-256 比对，不一致的文件直接丢弃：

| 文件 | 来源 | 放到 |
|---|---|---|
| 识牌模型 `best.onnx`（默认 yolov11s，`--yolo n s m` 可选） | hey-three/han-card-tracker | `yolo/weights/<规格>/` |
| DouZero ResNet 出牌模型 3 个 `.ckpt` | pumpkinjw/jjdouzeroAuto | `douzero/weights/resnet/` |

已经在本机克隆过这两个仓库时，可以不联网：

```powershell
python scripts/fetch_models.py --from-dir D:\code\han-card-tracker D:\code\jjdouzeroAuto
```

安全措施：`.ckpt` 只用 `torch.load(weights_only=True)` 读取，只接受张量，不执行文件里的任何 Python 对象；ONNX 本身不含可执行代码；任何未登记、哈希不符的文件都拒绝加载。

## 2. 准备按钮模板

自动操作靠模板匹配找“出牌”“不出”“要不起”“叫分”等按钮。模板是 JJ 界面截图，不随仓库分发，需要在你自己电脑上准备，放在 `config/jj_buttons/`（已被 git 忽略）。

**方法 A：从 jjdouzeroAuto 导入（最快，可能与你的 JJ 版本不完全一致）**

```powershell
python -m utils.button_templates import-jjdouzero D:\code\jjdouzeroAuto
```

**方法 B：自己截取（推荐，最准）**

1. 打开 JJ 斗地主，等到界面出现要截取的按钮（例如轮到你出牌时的“出牌”“不出”）。
2. 截取窗口：

   ```powershell
   python -m utils.button_templates capture --window JJ斗地主
   ```

3. 用“画图”打开生成的 `config/jj_buttons/_shot_*.png`，把鼠标放到按钮左上角和右下角，记下左下角显示的像素坐标，然后裁剪：

   ```powershell
   python -m utils.button_templates crop --image config\jj_buttons\_shot_XXXX.png --name play --box 610 520 700 560
   ```

4. 用同一张截图核对是否能找到：

   ```powershell
   python -m utils.button_templates check --image config\jj_buttons\_shot_XXXX.png
   ```

按钮名称与 `config/jj_buttons.yaml` 一致：

| 名称 | 按钮 | 是否必需 |
|---|---|---|
| `play` / `pass` / `cannot_beat` | 出牌 / 不出 / 要不起 | 自动出牌必需 |
| `bid_pass` `bid_1` `bid_2` `bid_3` | 不叫 / 1分 / 2分 / 3分 | 叫分模式需要 |
| `call_landlord` `no_call` `rob_landlord` `no_rob` | 叫地主 / 不叫 / 抢地主 / 不抢 | 叫抢模式需要 |
| `double` / `no_double` | 加倍 / 不加倍 | 可选；没有“不加倍”时等待游戏默认 |
| `continue` | 继续游戏 / 再来一局 | 可选，`auto_continue: true` 才会点 |
| `trusteeship` `confirm` `dialog` | 托管中 / 确认弹窗 / 其他弹窗 | 只用于识别后暂停，不会点击 |

缺少某个模板只会让对应功能不可用。缺少必需模板时状态栏会提示。截取时的窗口宽度会自动记在 `config/jj_buttons/widths.yaml`，JJ 窗口变大变小时模板会按比例缩放；但最好保持截取模板时的窗口大小。

## 3. 布局与窗口摆放

- 和记牌一样，先在“设置”里选好 JJ 窗口的布局（推荐“可视化编辑”框选五个区域）。**手牌区要框得足够高，能包住被点起来的牌**（选中的牌会上移）。
- 开启 AI 后，每一帧都会对整图识别全部五个区域（不再使用两阶段拼图），GPU 负担会比纯记牌大一些。
- **记牌器窗口不要盖住 JJ 窗口。** 截图是从屏幕上截的，被盖住的部分识别不到；点击前也会检查点击点是否在 JJ 窗口上，被盖住就暂停、不点击。
- JJ 窗口在一局中不要移动或缩放；移动会使正在进行的操作暂停。

## 4. 先用“只给建议”验收

1. 在开局前（发牌前）选择 “AI：只给建议”。
2. 状态行会显示：阶段 · 角色（地主/地主上家/地主下家）· 建议，以及模型前三候选和估值。
3. 至少观察几局，核对：
   - 叫分时的手牌强度和建议是否合理；
   - 底牌亮出后能否识别三张底牌；
   - 轮到你时角色判断是否正确，建议出的牌是否在你手里且合规；
   - 对手出牌、不出是否都被正确记录（出现“牌局记录与画面不一致”说明识别漏了牌）。
4. 中途才打开的局没有开局记录，会显示“本局开始时未确认三张底牌”，等下一局即可。

## 5. 开启“自动操作”

选择 “AI：自动操作” 并在提示框中确认。之后每一步都按以下顺序进行，任何一步不符合预期都会**暂停到本局结束**（下一局自动恢复，可在 `config/automation.yaml` 关闭 `resume_next_round`）：

1. 连续 3 帧画面完全一致才行动（`required_frames`）；
2. 根据识别到的完整出牌历史校验规则和张数，不一致不行动；
3. DouZero 只在合法动作中选择；
4. 按**当前帧真实牌框**逐张点选，重复牌点选择不同的牌；
5. 重新截图确认被选起来的牌正好是要出的牌，不符最多纠正 1 次（`max_corrections`），再不符暂停，不会连点；
6. 点“出牌”（或“不出/要不起”），再截图确认手牌减少了相应张数、按钮消失；
7. 3 秒内画面没有预期变化（`verify_timeout`）即暂停。

### 停止方式

- 按 **F12**（全局热键，JJ 在前台也有效，可在 `stop_hotkey` 修改）；
- 点主窗口红色“紧急停止”；
- 自动点击过程中**移动鼠标**也会立即停止（视为你接管）；
- 关闭程序。

紧急停止后模式变为“关闭”，必须手动重新选择才能再开启。

### 何时会暂停

| 提示 | 含义 |
|---|---|
| 检测到未处理的界面: trusteeship/confirm/dialog | 出现托管或弹窗，请手动处理 |
| 牌局记录与画面不一致 | 某一手牌漏识别或误识别，本回合不行动（可能需要你手动出牌） |
| 选中的牌与计划不一致 | 点选没有生效或手牌区没框住选起的牌 |
| 操作超时未生效 | 点击没有被游戏接受（例如 JJ 以管理员权限运行而本程序不是） |
| 点击点被其他窗口遮挡 / 目标窗口已移动 | 见第 3 节 |

如果 JJ 以管理员权限运行，本程序也需要以管理员身份启动，否则 Windows 会拦截模拟点击。

## 6. 参数

全部在 `config/automation.yaml`，修改后“重启识别”生效：

| 键 | 默认 | 说明 |
|---|---|---|
| `douzero_model` | resnet | `douzero/weights/` 下的目录；也支持 DouZero 原版 LSTM 权重（`landlord.ckpt` 等，需自行登记到清单） |
| `required_frames` | 3 | 行动前连续一致帧数 |
| `raise_ratio` | 0.3 | 牌上移超过牌框高度的该比例视为已选中 |
| `verify_timeout` | 3.0 | 点击后等待画面变化的秒数 |
| `max_corrections` | 1 | 选牌纠正次数 |
| `resume_next_round` | true | 暂停后下一局自动恢复 |
| `auto_continue` | false | 自动点击“继续游戏” |
| `round_end_seconds` | 3.0 | 底牌区连续为空多久算一局结束 |
| `stop_hotkey` | F12 | F1~F12 / PAUSE / SCROLLLOCK |
| `bidding.bid_1/2/3`、`bidding.double` | 6/8/10/11 | 叫分和加倍阈值 |

手牌强度 = 大王 4 + 小王 3 + 每张 2 记 2 + 每张 A 记 1 + 每个炸弹 4 + 王炸再加 2。强度 ≥ `bid_3` 叫 3 分（叫抢模式下抢地主），≥ `bid_2` 叫 2 分，≥ `bid_1` 叫 1 分（叫抢模式下叫地主），否则不叫。

## 7. 角色与出牌历史如何得到

- 底牌区出现三张牌时开始记录本局。
- 第一次轮到你：手牌 20 张且没人出过牌 → 你是地主；17 张时，下家已出过牌 → 下家是地主（你是地主上家），否则上家出过 → 上家是地主（你是地主下家）。
- 之后每次轮到你，自上次以来每家正好行动一次；记牌器确认的新出牌即为该家出牌，没有新出牌即为“不出”。这些记录按规则逐手校验（顺序、牌型、能否压过、张数），任何矛盾都不会交给模型。

## 已验证与未验证

- 已验证（Linux 自动测试）：规则、编码、角色推断、选牌规划、按钮模板匹配（合成图）、受保护点击（假输入）、闭环状态机、配置校验；真实 ResNet 权重经清单校验后加载并给出合理建议。
- **未验证**：真实 JJ 客户端上的截图识别、按钮模板、点击是否被游戏接受、长时间连续对局。请务必先用“只给建议”模式在你的电脑上验收。
