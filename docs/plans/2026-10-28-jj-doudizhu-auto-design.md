# JJ 斗地主自动操作助手设计

日期：2026-10-28

## 1. 目标与范围

本项目在 macOS 上开发、审计和进行离线测试，在 Windows 上运行并自动操作 JJ 大厅中的标准三人斗地主。

第一版包含：

- 识别本家手牌、三张底牌、三家出牌和玩家身份；
- 识别叫分、抢地主、加倍、不出和出牌等必要按钮；
- 使用 DouZero 计算叫牌和出牌动作；
- 根据当前画面中的真实牌框选择牌张并点击按钮；
- 点击后重新识别和验证，失败时暂停；
- 提供观察模式、自动模式和独立的紧急停止机制。

第一版不支持欢乐、癞子、二人、四人等玩法，不点击登录、充值、广告、领奖或其他未知界面，不读取游戏进程内存，也不尝试规避游戏平台检测。使用者需要自行确认并遵守目标软件的适用规则。

## 2. 技术路线

以 `han-card-tracker` 的 Windows 截图、YOLO 识牌、布局、诊断和测试架构为主工程。`jjdouzeroAuto` 仅作为行为参考，不直接复制其 GPL-3.0 主循环、硬编码坐标和窗口控制代码。

决策层基于原始 `kwai/DouZero` 的 Apache-2.0 代码和合规来源模型实现。新项目保留第三方版权与许可证说明，记录所有模型的来源、哈希和转换过程。

主模块如下：

| 模块 | 职责 |
|---|---|
| UI 主进程 | 显示牌局、AI 动作、运行状态、观察/自动模式和紧急停止 |
| 捕获与识别进程 | 捕获指定 JJ 窗口，识别牌面、牌框、按钮及置信度 |
| 牌局状态机 | 管理等待、叫地主、出牌、验证、暂停和结束状态 |
| DouZero 决策层 | 根据已确认牌局状态生成合法叫牌或出牌动作 |
| Windows 执行层 | 使用当前牌框和按钮框实施点击，不依赖绝对屏幕坐标 |
| 诊断旁路 | 保存脱敏的截图哈希、识别结果、决策、点击和状态转换 |

## 3. 数据流

截图不会直接触发点击。识别进程先输出牌面、坐标、按钮、窗口尺寸和置信度；结果连续多帧一致且符合牌局规则后，状态机才接受。

本家回合的数据流为：

1. 捕获 JJ 窗口并确认窗口未被遮挡、移动或改变比例；
2. 识别手牌、上一手牌、按钮和当前角色；
3. 将稳定的牌局状态交给 DouZero；
4. 校验返回动作属于当前合法动作集合；
5. 根据当前帧牌框定位并选择目标牌；
6. 重新截图确认选牌结果；
7. 识别并点击“出牌”或“不出”；
8. 再次截图，确认手牌数量和回合状态按预期变化；
9. 验证成功后才把动作写入正式牌局历史。

叫地主阶段使用相同原则：只有状态机确认当前轮到本家，并识别出合法按钮后，才允许执行 DouZero 的叫牌决策。

## 4. 故障保护

- 自动模式默认关闭，每次启动需要用户主动开启；
- 观察模式运行完整识别和决策，但不产生鼠标输入；
- 识别置信度不足、连续帧不一致、动作不合法或区域未知时不操作；
- 每次点击后必须验证结果，不能仅因已发送鼠标事件就视为成功；
- 纠正点击次数有严格上限，超过上限立即暂停；
- 窗口被遮挡、移动、缩放，截图失败或出现未知弹窗时立即暂停；
- 不自动处理登录、充值、广告、领奖、验证码或未知按钮；
- 紧急停止独立于 UI 和推理进程，即使模型卡住也能停止自动输入；
- 故障恢复必须重新确认窗口、布局、牌局状态和当前回合，不能从旧动作继续。

## 5. 模型与供应链安全

PyTorch `.pt` 文件可能包含 pickle 数据，不能因为来自 GitHub 就视为安全。临时目录中的 `n.pt`、`s.pt` 和 `m.pt` 在审计前不加载。

正式流程为：

1. 核验模型原始下载地址、许可证和发布者；
2. 计算并记录 SHA-256；
3. 在隔离环境中检查和转换模型；
4. Windows 正式运行优先使用 ONNX 等不含任意 Python 对象的格式；
5. 发布包附模型清单、哈希、转换命令和输入输出契约；
6. 锁定 Python 依赖并生成第三方许可证与软件物料清单；
7. 正式程序默认不访问网络，不包含遥测、远程控制或自动更新。

## 6. 测试策略

### 6.1 Mac 单元测试

验证斗地主规则、牌局状态转换、动作合法性、牌框映射、执行计划生成、错误路径和暂停条件。平台相关接口通过适配器注入，测试不产生真实鼠标输入。

### 6.2 离线回放

使用脱敏后的 JJ 截图和录屏覆盖三种身份、叫地主、出牌、不出、炸弹、王炸、换行手牌、窗口缩放、动画、遮挡和一局结束。回放使用与正式程序相同的识别和状态机路径。

### 6.3 Windows 观察模式

在真实 JJ 客户端运行截图、识别和 DouZero 决策，只显示计划点击位置。通过诊断包核对识别、回合和动作，不执行点击。

### 6.4 Windows 自动模式

先在低风险环境进行受限自动测试。确认每步验证、错误暂停和紧急停止可靠后，才进行连续完整牌局验收。实机验收需要目标 Windows 电脑提供截图、诊断包或远程测试环境。

## 7. 发布方式

GitHub 仓库保存可审计源码、测试、文档和构建配置，不保存账号、Cookie、令牌、个人配置或未脱敏的真实截图。

GitHub Actions 在干净的 Windows 环境运行测试并构建发布包。每个 Release 提供：

- 对应源码提交；
- Windows 压缩包；
- SHA-256 校验文件；
- 依赖和第三方许可证清单；
- 模型来源及哈希；
- 构建与测试日志；
- 已知限制和实机验证范围。

从自己的 GitHub 下载不能带来绝对安全保证。安全目标是让源码、模型、依赖、构建和测试证据均可追溯、可检查和尽可能可复现。
